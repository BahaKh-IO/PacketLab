1. Ce qui peut mal tourner

Un réseau ne garantit pas que tout ce qui est envoyé arrive intact, dans l'ordre et une seule fois. Plusieurs types d'erreurs existent :

ErreurCause possibleConséquence
Erreur de transmissionBruit, interférences sur le supportDes bits sont modifiés
PerteFile d'attente pleine dans un routeur, trame abîmée puis jetéeUn morceau n'arrive jamais
Retard, désordreChemins ou attentes différentsLes morceaux arrivent dans le désordre
DoublonUn morceau envoyé deux foisLe même morceau arrive deux fois

2. Détecter les erreurs de transmission

L'émetteur ajoute aux données quelques bits de contrôle calculés à partir d'elles. Le récepteur refait le calcul : si le résultat diffère, il sait que la trame a été abîmée et il la jette. Le CRC (contrôle de redondance cyclique, ou code polynomial) est le code le plus utilisé : c'est lui qui remplit le FCS des trames Ethernet. Il détecte les erreurs, il ne les corrige pas : une trame jetée devient une perte, que l'on traite comme ci-dessous.

3. Récupérer les pertes : numéros, acquittements, temporisateurs

  1. Le message est découpé en morceaux numérotés.
  2. Le récepteur range chaque morceau à sa place et renvoie un acquittement (ACK) qui porte son numéro.
  3. L'émetteur arme un temporisateur pour chaque morceau envoyé. L'ACK l'annule.
  4. Si le temporisateur expire sans ACK, l'émetteur réémet le morceau et réarme le temporisateur.
  5. Si un morceau arrive en double, le récepteur le reconnaît à son numéro, le jette, mais l'acquitte quand même : son premier ACK s'est peut-être perdu.

Exemple : le morceau 3 est perdu

Dans le Labo fiabilité, un aller-retour normal (morceau puis ACK) dure 120 ms et le temporisateur 200 ms. Le morceau 3, envoyé à 20 ms, est perdu au routeur B. À 220 ms, son temporisateur expire : il est réémis et arrive à 280 ms. Le message est complet. Sans récupération, la case 3 reste vide pour toujours.

4. Bien régler le temporisateur

  • Trop court : il expire alors que l'ACK était en route. L'émetteur réémet pour rien et crée des doublons.
  • Trop long : après une vraie perte, l'émetteur attend longtemps avant de réagir.

Il doit donc dépasser un peu l'aller-retour normal. Les protocoles réels mesurent cet aller-retour en permanence pour ajuster leur temporisateur.

5. Envoyer et attendre, ou anticiper

  • Envoyer et attendre (Send and Wait) : un seul morceau en route ; on attend son ACK avant d'envoyer le suivant. Très simple, mais le lien reste inutilisé pendant chaque attente.
  • Fenêtre d'anticipation (Sliding Window) : jusqu'à W morceaux peuvent être envoyés sans attendre leurs ACK. Le lien est bien mieux utilisé ; les numéros et les ACK restent indispensables pour savoir quoi réémettre.

Le labo de PacketLab envoie tous les morceaux sans attendre, comme une très grande fenêtre. C'est un modèle simplifié : ce n'est pas TCP, qui numérote les octets et utilise des acquittements cumulatifs.

À retenir
