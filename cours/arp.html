1. Le problème

Une machine veut envoyer un paquet. Elle connaît l'adresse IP de la destination, mais pour construire la trame Ethernet, il lui faut une adresse MAC. Le protocole ARP (Address Resolution Protocol) sert à faire ce lien : il trouve la MAC qui correspond à une adresse IP du réseau local.

2. Quelle IP chercher ?

La machine décide d'abord à qui elle va remettre la trame, grâce à son masque :

  • la destination est dans son réseau : elle cherche la MAC de la destination ;
  • la destination est ailleurs : elle cherche la MAC de sa passerelle par défaut.

On ne demande jamais par ARP la MAC d'une machine située dans un autre réseau : elle ne répondrait pas, car la requête ne lui parviendrait pas.

3. L'échange ARP

  1. Requête : « Qui a 192.168.1.1 ? Répondez à 192.168.1.10, AA:AA:AA:00:00:0A. » Elle est envoyée en diffusion (MAC destination FF:FF:FF:FF:FF:FF), car l'émetteur ne sait pas encore à qui l'adresser. Dans le message ARP, le champ « MAC cible » est vide (00:00:00:00:00:00).
  2. Toutes les machines du réseau reçoivent la requête. Celles dont ce n'est pas l'adresse IP l'ignorent.
  3. Réponse : la machine concernée répond « 192.168.1.1, c'est moi : 11:11:11:00:00:01 ». La réponse part en unicast, directement vers le demandeur, dont la MAC figurait dans la requête.
  4. Le demandeur range le couple IP → MAC dans sa table ARP, puis envoie enfin la trame qu'il gardait en attente.

Au passage, la machine qui répond a appris la MAC du demandeur : elle la note aussi. Si elle doit lui écrire ensuite, elle n'aura pas besoin de faire d'ARP.

4. La table ARP

La table ARP (ou cache ARP) garde les correspondances déjà apprises. Tant qu'une entrée existe, la machine construit la trame tout de suite, sans redemander. Dans les vrais systèmes, les entrées expirent après quelques minutes pour suivre les changements du réseau ; dans PacketLab, elles commencent vides et restent pendant toute la simulation.

5. ARP et les routeurs

Une requête ARP est une diffusion : elle ne sort pas de son domaine de diffusion, car les routeurs ne relaient pas les diffusions. Conséquence : sur un chemin à plusieurs routeurs, chaque équipement refait son propre ARP pour le tronçon suivant. Un routeur se comporte comme un PC sur chacun de ses réseaux : il met le paquet de côté, demande la MAC du prochain saut, puis transmet.

Exemple : trois ARP pour un seul paquet

PC-A → PC-B dans la topologie mixte : PC-A demande la MAC de 192.168.1.1 (R1), R1 demande celle de 10.0.0.2 (R2), R2 demande celle de 192.168.2.20 (PC-B). Si l'on renvoie un deuxième paquet juste après, plus aucun ARP n'est nécessaire.

À retenir

  • ARP trouve la MAC d'une IP du réseau local.
  • Destination locale : ARP pour elle ; sinon : ARP pour la passerelle.
  • Requête en diffusion, réponse en unicast, résultat gardé dans la table ARP.
  • ARP ne traverse pas les routeurs : chaque tronçon a son propre ARP.
