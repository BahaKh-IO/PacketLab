1. Relier des réseaux

Un commutateur relie des machines d'un même réseau. Pour passer d'un réseau à un autre, il faut un routeur. Il travaille dans la couche 3 (réseau) : il lit l'adresse IP destination du paquet et choisit par où l'envoyer. Chacune de ses interfaces appartient à un réseau différent et possède sa propre adresse IP et sa propre MAC.

2. La table de routage

Chaque ligne de la table de routage associe un réseau à une sortie :

RéseauProchain sautInterface
192.168.1.0/24directement connectée0
10.0.0.0/30directement connectée1
192.168.2.0/2410.0.0.2e1
  • Directement connecté : le réseau est relié à une interface du routeur ; la destination est sur le même réseau que lui, il lui livre le paquet lui-même.
  • Prochain saut : l'adresse IP du routeur suivant, à qui confier le paquet.

Ces routes peuvent être écrites à la main (routage statique, celui de PacketLab) ou apprises automatiquement par un protocole de routage dynamique (comme OSPF), qui sait s'adapter aux pannes.

3. Choisir une route : le plus long préfixe

Pour une destination, le routeur cherche toutes les routes dont le réseau contient l'adresse. S'il y en a plusieurs, il prend la plus précise, celle qui a le masque le plus long.

Exemple

Routes : 10.0.0.0/8 via A ; 10.1.0.0/16 via B ; 10.1.2.0/24 via C ; 0.0.0.0/0 via D.

  • 10.1.2.9 : les quatre conviennent, la /24 gagne → C.
  • 10.1.7.1 : /8, /16 et /0 conviennent, la /16 gagne → B.
  • 172.16.0.1 : seule la route par défaut convient → D.

La route par défaut 0.0.0.0/0 convient à toutes les adresses : elle ne sert que si rien de plus précis n'existe. Sans elle, un paquet sans route est détruit.

4. Ce que fait le routeur au paquet

  1. Il reçoit la trame (elle lui est adressée : MAC destination = la sienne) et en sort le paquet IP.
  2. Il enlève 1 au TTL. S'il tombe à 0, le paquet est détruit.
  3. Il choisit la route et en déduit le prochain saut.
  4. Il cherche la MAC du prochain saut (table ARP, ou requête ARP).
  5. Il construit une nouvelle trame : MAC source = son interface de sortie, MAC destination = le prochain saut.

Les adresses IP source et destination ne changent pas (sans NAT) : elles désignent toujours les deux extrémités de l'échange.

5. Le TTL

Le TTL (Time To Live, durée de vie) est un compteur de sauts placé dans l'en-tête IP par l'émetteur, souvent à 64. Chaque routeur l'abaisse de 1. Il protège le réseau contre les boucles de routage : si deux routeurs se renvoient un paquet à cause d'une erreur de configuration, le TTL finit par atteindre 0 et le paquet disparaît au lieu de tourner indéfiniment. Un vrai routeur prévient alors la source par un message ICMP « temps dépassé » ; c'est ce mécanisme qu'utilise la commande traceroute.

6. Le routage se décide saut par saut

Le paquet ne contient pas son itinéraire : chaque routeur décide seul, avec sa propre table. Rien n'oblige le retour à suivre le même chemin que l'aller.

Dans PacketLab

Dans la maillée, l'aller passe par R2 et le retour par R3. Supprimez une route : R1 utilise sa route par défaut. Créez une boucle : le TTL descend jusqu'à 0.

À retenir

  • Le routeur décide avec l'IP destination et sa table de routage.
  • Plusieurs routes conviennent : le plus long préfixe gagne ; 0.0.0.0/0 est la route par défaut.
  • À chaque routeur : TTL − 1, nouvelles MAC ; les IP restent.
  • Le chemin se décide saut par saut.
