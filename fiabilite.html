Labo fiabilité

Perdez ou retardez des morceaux d'un message, puis comparez la livraison avec et sans retransmission.

Script d'incidents : cliquez sur un morceau pour le perdre ou le retarder

Normal → perdu (disparaît au routeur B) → retard court 60 ms (arrive dans le désordre) → retard long 300 ms (plus long que le délai d'attente).

Mode

Écrivez le script d'incidents, choisissez un mode, puis cliquez sur « Lancer ».

Clavier : ← → instant par instant · Espace lecture/pause · R rejouer

3 morceau 3 morceau renvoyé A3 ACK 3 morceau perdu · Émetteur : n envoyé n délai expiré n confirmé

Résultats

Temps total : instant où le message est complet chez le récepteur, ou fin de la simulation s'il reste troué.

À propos du modèle

Ce labo montre l'idée de l'acquittement et de la retransmission. C'est un modèle simplifié, ce n'est pas TCP :

  • Le chemin est fixe : émetteur → routeur A → routeur B → récepteur, 20 ms par lien.
  • L'émetteur envoie un morceau toutes les 10 ms, sans attendre les ACK (pas de fenêtre, pas de contrôle de congestion).
  • Le récepteur envoie un ACK par morceau (pas d'ACK cumulatif) ; dans ce modèle, les ACK ne se perdent jamais.
  • Le délai d'attente est fixe : ms par morceau (TCP le calcule à partir des temps mesurés).
  • Une perte ou un retard du script ne touche que le premier envoi du morceau ; le renvoi passe toujours.
  • Les morceaux sont numérotés 1, 2, 3… (TCP numérote les octets).
  • Le même script donne toujours exactement la même exécution : rien n'est tiré au hasard.
